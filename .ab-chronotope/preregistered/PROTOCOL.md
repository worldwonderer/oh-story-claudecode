# 预注册协议 — 「拒绝概述」确证性重复实验

**冻结时间**：本文件与 `analysis.py` 在任何一份确证数据产生之前提交。提交后不修改；
如需修改，必须在文件末尾追加「协议偏离」条目并说明原因，不得静默改写。

前序探索性实验（60 份成稿、8 个臂）已确定方向。本轮**只做确证**，不再探索。

## 1. 假设（唯一主假设）

**H1**：在 spawn prompt 中加入「拒绝概述」块（PR #373 采用的去 case 版，下称 **v2**），
相比不加（**base**），会提高成稿中**不可替换具体细节**的数量。

次要假设（不用于判定 PR 收益，只用于排除副作用）：

- **H2a**：v2 不降低细纲情节点覆盖率。
- **H2b**：v2 不增加题材串味细节。
- **H2c**：v2 不把字数推出用户带（目标 ±15%）。

## 2. 主指标（primary endpoint）

**NSD = 不可替换具体细节数（non-substitutable detail count）**，每份成稿一个整数。

用两段互不见面的流程产生，两段的执行体都**不评价好坏**：

1. **抽取**：抽取员只拿到一份成稿（不知道臂别、不知道有对照），逐条列出文中
   **具体到可以被复述的细节**原文（每条 ≤20 字）。只抽取，不判断。
2. **可替换性判定**：判定员**不看正文**，只拿到上一步的候选清单 + 本书题材设定一句话，
   对每条独立回答：「把这一条原样放进另一本书、另一个角色身上，还成不成立？」
   - 成立（可搬） → 通用填充，不计入
   - 不成立（搬不走） → 计入 NSD

NSD 由此是一个**计数**，不是评分；两名执行体各自的任务都很窄，谁都没有被问「哪份更好」。

## 3. 次要指标

- **COV**：细纲情节点中被实际落地的条数（由抽取员在同一次调用中顺带判定，0–N）。
- **OFF**：判定员标记为「明显不属于本书题材/设定」的细节条数。
- **CHARS**：`visible_chars_v1` 字数，是否落在目标 ±15% 用户带内（布尔）。
- **QUAL**：单份 1–5 成品度评分（仅作参考，**不作为 PR 收益依据**，因为它与前序实验同源、
  且已知存在评委自我偏好）。

## 4. 评审设计

- **主评委 = GPT-5.6（codex exec）**，与前序全部实验的 Claude 评委架构独立。
- **单份盲评**：每次调用只给一份成稿，评审者看不到任何对照组，无法通过对比推断分组。
- **每份成稿由 3 名独立抽取员各抽一次**；NSD 取三次的**中位数**，同时报告三者一致性。
- 成稿文件名在进入评审前统一改为哈希标签，揭盲表另存，评审侧不可见。
- **Claude 侧仅作次要复核**，其结果单独报告，不并入主判定。

## 5. 样本与分层

写作全部走两段式真路径（真 checkpoint、真组装），除被测 prompt 块外材料逐字相同。

| 分层 | 取值 |
|---|---|
| 章节 | 第 8 章（纯双人戏，细纲无集合）／第 12 章（可采访集合）／第 14 章（抽象网络集合）／《盘龙》第 6 章（换书换题材·西幻） |
| 臂 | base ／ v2 |
| 模型 | GPT-5.6（主，每格 n=3）；Claude Opus 5（次，仅第 12 章与《盘龙》第 6 章，每格 n=2） |

主分析样本量：4 章 × 2 臂 × 3 次 = **24 份**。次要样本：2 章 × 2 臂 × 2 次 = 8 份。

## 6. 统计分析（先冻结，见 analysis.py）

- 主检验：对 NSD 做**分层置换检验**（按章节分层，仅在臂标签内置换），10000 次重排，
  双尾 p 值。效应量报告为**按章节配对后的平均差**及其 bootstrap 95% CI（10000 次重抽）。
- 判定阈值：**p < 0.05 且 CI 下界 > 0** 才算 H1 成立。
- 次要指标只做描述性报告与区间估计，不做假设检验（避免多重比较）。
- 评委间一致性：报告三名抽取员 NSD 的组内相关（ICC(2,1) 的点估计）与两两 Spearman ρ。
- **不做任何数据依赖的子集分析**；若某格运行失败，按实际 n 分析并在报告中标注。

## 7. 事先声明的可证伪结果

以下任一发生，即认为 PR #373 的收益**未被确证**，应在 PR 上如实记录：

- NSD 的置换检验 p ≥ 0.05，或 bootstrap CI 下界 ≤ 0；
- 或 COV 在 v2 侧平均下降 ≥ 1 个情节点（说明具体度是靠漏点换来的）；
- 或 OFF 在 v2 侧平均上升 ≥ 0.5 条（说明具体度是靠串味换来的）；
- 或 v2 侧落在用户带外的比例高于 base 侧 ≥ 25 个百分点。

## 8. 已知且不打算修的局限

- spawn prompt 是按 `workflow-chapter.md` 步骤 7 手工重建的，不是真实 skill 运行时产物；
  臂间逐字相同，因此不威胁组间比较，但限制外部效度。
- 《盘龙》项目 fixture 由拆文摘要手工拼成，无真实设定/追踪目录。
- 全部评审仍是 LLM，没有人类读者。NSD 衡量的是「细节的不可替换性」，
  不等于「读者更愿意付费」。
- 作者（本次执行者）设计了 prompt、选了章节、写了分析脚本，未做执行者盲。
  缓解手段是本协议与分析脚本在数据产生前冻结提交。
