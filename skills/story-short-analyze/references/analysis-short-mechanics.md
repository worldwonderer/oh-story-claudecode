# 短篇源文核心机制分析

> 分析短篇的核心梗如何在有限全文内被验证、变奏和结算。这里的“循环”只指同一机制在源文内的有限复现，不承担长线扩张指标。

## 核心问题

核心机制不是题材标签或金手指名称，而是角色反复用什么选择处理冲突，读者因此持续期待什么。

用一句话表达：

```text
当 {触发条件} 出现，角色通过 {关键选择/手段} 获得 {局部结果}，同时承担 {限制/代价}；终局由 {不可逆选择} 结算。
```

## 机制证据矩阵

| 维度 | 观察问题 | 证据要求 |
|---|---|---|
| 触发 | 什么事件让机制启动？ | 首次出现的位置与前置条件 |
| 输入 | 角色必须投入什么？ | 时间、关系、名誉、资源、秘密或选择 |
| 处理 | 机制具体改变了哪一步解法？ | 可见行动，不只设定说明 |
| 输出 | 每次运转交付了什么局部结果？ | 信息、关系、风险、资源或身份变化 |
| 限制 | 什么情况下机制失效或不能继续？ | 失败、到期、冲突规则或现实阻力 |
| 代价 | 谁为推进付账，代价是否落在同一主线？ | 运转后的实际后果 |
| 变奏 | 后一次与前一次相比改变了什么？ | 对象、解释、选择或代价的变化 |
| 结算 | 终局是否仍需要人物作选择？ | 最后不可逆行动及其后果 |

## 有限复现类型

| 类型 | 判断标准 | 风险 |
|---|---|---|
| 单次触发 | 机制只改变一个关键节点，随后处理后果 | 设定解释过长会挤压人物选择 |
| 递进复现 | 同一规则数次出现，每次提高代价或改变解释 | 只提高数值、不改变选择会显重复 |
| 证据接力 | 机制依次改变证据来源、解释和归属 | 证据若不影响行动，会变成资料堆积 |
| 关系接力 | 同一矛盾在不同关系中暴露新的责任 | 新角色只为提供答案会稀释主线 |
| 误判修正 | 角色基于机制形成阶段答案，再被新证据纠正 | 后层若让前层事实全部作废，会显作弊 |
| 报应对应 | 旧伤害与后果逐项建立因果回声 | 天降惩罚会削弱角色代理权 |

## 系统与脑洞短篇

出现系统、能力或异常规则时，额外检查：

- 规则是否在第一次关键使用前可理解。
- 后续变化是既有规则的后果，还是临时新增功能。
- 能力解决的是局部障碍，还是替人物完成证据、关系和伦理选择。
- 能力退出、转移或失效后，主线是否仍由人物行动收束。
- 结尾兑现的是开篇承诺，还是突然转成财富、战力或更大世界展示。

系统只触发少数几次、规则不升级，完全可以构成短篇核心机制；不要因此判为“不具备长线潜力”，短篇不承担长线循环义务。

## 主角代理权

对每个决定性节点记录四个角色：谁取得信息、谁验证、谁解释、谁选择使用。主角不必独占所有动作，但必须拥有影响终局责任或关系的不可替代选择。

若关键答案全由系统、盟友、反派口供或巧合送达，报告为“机制/配角夺走因果权”，并引用具体位置；不要用笼统的“主角不够主动”。

## 机制与题材的关系

- 题材说明故事主要在结算什么；机制说明文本用什么因果反复推进。
- 悬疑、系统、重生、灵魂视角可能是主类型，也可能只是家庭、职场或关系主线的工具。
- 删除机制后若主线仍原样成立，机制只是装饰。
- 删除题材冲突后机制失去目标，说明机制服从该题材主线。

## 报告格式

```markdown
核心机制：{一句话}
运转证据：{按出现顺序列位置、输入、输出、代价}
有限复现类型：{类型及依据}
规则一致性：{成立/存在缺口/证据不足}
主角代理权：{取得、验证、解释、使用的所有权}
终局结算：{机制是否退出，人物选择是否接管}
可复用功能：{抽象功能}
失败条件：{移植时最容易失效的因果}
```

## 边界

- 不评价机制能否支撑几十万字、多少卷或多少次升级。
- 不要求固定复现次数；记录源文实际次数及每次是否改变因果。
- 不把写作建议、赛道选择或创新配方写进拆文报告。
- 证据不足时标“待复核”，不替源文补规则或作者意图。
