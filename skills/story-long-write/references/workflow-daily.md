# workflow-daily.md：日更续写工作流

本文件为"日更续写"场景的完整指引。SKILL.md 路由到本文件后，按以下流程执行。

> **日更准备步骤**：每章写作前 4 步——状态筛选 + 题材正文提示卡召回 + 文风召回 + 意图确认，嵌入 Step 2 逐章循环。读者契约、主角代理权、期待债、终局储备统一参 `reader-contract-and-progression.md`。
>
> Step 2 必读 / 生成五类写前资料：
> 1. `{对标书路径}/剧情/情绪模块.md`（读者需求 / 情绪引擎 + 可复现模块；缺失按下方「模块/节奏缺失」规则停下修复）
> 2. `{对标书路径}/剧情/节奏.md`（关键信息推进 + 情绪触动点 + 爆发节奏；缺失按下方「模块/节奏缺失」规则停下修复）
> 3. `设定/题材正文提示卡.md`（题材边界 / 核心逻辑 / 读者期待 / 节奏密度；缺失时用 `设定/题材定位.md` + `references/genre-prose-cards.md` 索引匹配并读取 `references/genre-prose-cards/{题材}.md` 单卡优先生成，`references/style-genre-modules.md` 通用流派兜底）
> 4. `{对标书路径}/文风.md`（整书级 ~4000 字，含原文锚点范例片段）
> 5. `{对标书路径}/章节/第K章_摘要.md`（按本章情绪/基调挑 1 章）；若同章存在 `第K章_深度拆解.md` 则加读，否则回退黄金三章深度拆解/文风文件里的可借鉴技巧
>
> 对标书路径查找：先 `{项目}/对标/{书名}/`，回退 `拆文库/{书名}/`。
>
> **题材正文提示卡**：优先读 `设定/题材正文提示卡.md`；缺失时不阻塞，先从 `设定/题材定位.md` 精确匹配 `references/genre-prose-cards.md` 索引，并只读取 `references/genre-prose-cards/{题材}.md` 题材单卡（高/中/低置信照原卡标注），无命中再从 `references/style-genre-modules.md` 抽取通用流派短 `genre_prose_card`。题材卡只管题材味和正文取舍，不改细纲、不覆盖情绪/节奏权威文件，也不接管句长/标点等文风细节。题材卡只在写手心里校准取舍，卡名/题材标签/置信度/条目/合规自评一律不写进正文。
>
> **自定义文风（`设定/文风.md`，优先级最高）**：主会话每章写作前直接读 `设定/文风.md`（不经 story-explorer——它只看 `对标/文风.md`）。存在且含实质内容（去空白 ≥200 字，或含「句长 / 标点 / 对话 / 锚点 / 笔调」风格小节且小节内有可执行约束：比例 / 例句 / 禁止或偏好描述）即进入「自定义文风模式」：它是本书既定笔调的**权威**风格基，narrative-writer 的句长带 / 标点节奏 / 对话潜台词 / 情绪交替以它为准；对标 / 拆文 `文风.md` 降级为「**参考**」——只供原文锚点范例与句长分布数值兜底，不再是被遵循的最终文风。空 / 仅空白 / 仅标题 / 占位 stub（待办 / 待补充 / ___）视为不存在。仅接管风格，**不覆盖** `剧情/情绪模块.md` / `剧情/节奏.md` 的情绪与节奏意图（同下「冲突规则」）。**硬门禁不让位**：`设定/文风.md` 里命中硬安全线的写法（`……`、破折号 `——`/`—`、段间空行、三五字碎句）仍按 narrative-writer 归一为句号 / 逗号 / 动作节拍 / 单 `\n`；自定义文风只接管句长 / 软标点节奏 / 潜台词 / 情绪交替（要让这些标记原样进正文须放宽题材硬门禁，本期不做）。
>
> **文风缺失**：**未进入自定义文风模式**时，对标书缺 `文风.md` 则停止本章写作、不 inline 生成，报错：「对标书 X 缺少 文风.md。请用 `/story-long-analyze` 跑 Stage 6 生成文风，再 `/story-import` 同步。」**已进入自定义文风模式则不 fail-fast**，用 `设定/文风.md` 继续。
>
> **模块/节奏缺失**：对标书缺 `剧情/情绪模块.md` 或 `剧情/节奏.md` 时停止本章准备，设置 `gaps.missing_primary_contract: true`，提示重跑 `/story-long-analyze` Stage 3+ 或重新 `/story-import`；不得用摘要文件拼装低置信替代品。
>
> **冲突规则**：`剧情/情绪模块.md` 与 `剧情/节奏.md` 是情绪和节奏的权威来源；`拆文报告.md`、`剧情/故事线.md` 是投影摘要；`文风.md` 只管风格。若摘要或文风与权威模块/节奏冲突，保留 `gaps.conflict`，正文意图跟随权威文件。
>
> **无对标项目**：无 `设定/文风.md` 时跳过「对标模块/节奏/题材卡/文风召回」，在「意图确认」标记"无对标参考"，不读不存在的文风、不阻塞、不警告；**有 `设定/文风.md`（自定义文风模式）则用它写作**——此时无对标可召回，情绪/节奏目标改从本书细纲「目标情绪」、卷纲、`设定/题材定位.md` 等内部材料取，`selected_emotion_module` / `rhythm_reference` 记「无」，不声称从对标召回。
>
> **多本对标书**：从 `设定/题材定位.md` 读 `主对标书` 字段；缺失时用 `对标/` 下字典序第一本并提示用户补字段。
>
> 完整写前准备逻辑见 `SKILL.md` 的 Phase 4。

---

## 适用条件

- 项目已有 `正文/` 和 `追踪/` 目录
- 用户明确说"日更""续写""继续写"，或明确指定"写第 N-M 章"
- 目标：每次会话写 2-3 章（4000-9000 字）

> **裸调用不进日更**：如果用户只是触发 `/story-long-write` / `$story-long-write`，没有说"日更/续写/继续写/写第N章/只写1章/逐章确认"，不得进入本 workflow。回到 `SKILL.md` 的"裸调用与停靠点"，只展示当前进度与可选命令，避免重启会话后自动写 3 章。

## Step 1：快速上下文加载

**可选：使用 story-explorer agent 批量加载上下文**。如果项目已部署 story-explorer agent（检查 `.claude/agents/story-explorer.md` 是否存在），可以用 `Agent(subagent_type: "story-explorer", prompt: "项目目录：{dir}\n查询类型：context_load\n查询参数：准备写第 {N} 章\n待处理事项选择结果：{下方脚本的 JSON}")` 执行 `context_load` 查询，一次获取全部写作上下文。spawn 返回后直接使用其 results，跳过下方手动加载步骤。如果 agent 不可用或返回不完整，回退到下方手动加载。无论是否使用 agent，都必须先运行下方待处理事项选择脚本；状态摘要里的索引只是显示信息，不是判断目录是否有事项的依据。

手动加载（默认方式）：

| 序号 | 文件 | 用途 | 如果不存在 |
|------|------|------|-----------|
| 1 | `追踪/上下文.md` | 写作状态摘要（≤12KB，整份读）；通常的日更状态都在这里，跨章事项按下方规则另读最多 6 个小文件 | 用本章细纲 + 最近 3 章正文按「状态摘要格式」新建；若存在 `.上下文迁移.json`，先恢复未完成的迁移，不走普通新建流程 |
| 2 | `追踪/伏笔.md` | **日更不读**（历史记录文件）。需要时按下方「旧信息查找步骤」按需查询 | 跳过 |
| 3 | `追踪/时间线.md` | **日更不读**（历史记录文件）。需要时按下方「旧信息查找步骤」按需查询 | 跳过 |
| 4 | `追踪/角色状态.md` | **日更不读**（历史记录文件）。角色当前状态从状态摘要 `## 在场角色` 取，缺则按需查询 | 跳过 |
| 5 | `追踪/逐章记录/第NNN章.md` | **日更不读**（逐章记录）。每章一个小文件，完整记录该章内容，后续以此为准 | 首次日更时创建目录 |
| 6 | `大纲/细纲_第{N}章.md` | 本章写作计划 | **必须先补建**，不允许跳过 |
| 7 | `大纲/卷纲_第X卷.md` | 卷契约、当前剧情单元、终局储备 | 旧版缺卷契约/剧情单元卡不阻塞：内存推断后写进状态摘要 `## 当前位置` 的「本卷主线」一行，完整判断过程记进本章 `追踪/逐章记录/第{NNN}章.md`；仅本轮明确补纲/改纲时回写卷纲，未知字段写 `[待补充]`；锁定卷纲绝不自动修改 |

**按需加载角色文件**：从细纲中提取本章涉及的角色名，按需加载 `设定/角色/{角色名}.md`。如果细纲中未列出角色，跳过。

**跨章事项检查（每章必做）**：`追踪/待处理事项/` 是所有未结清跨章事项的完整记录，每个事项单独一个文件，单个文件不超过 300 字；状态摘要只显示其中最早的事项。先检查状态摘要里的旧格式固定事项：若缺少 `记录编号=`，先用下方 `--next-name` 为它创建单项文件、重新读取并确认内容，再把返回的 `record_id` 写回摘要。数出当前 `## 下一章必做事项` 中不以 `[固定｜` 开头的普通事项，然后用可用的 Python 命令（依次尝试 `python3` / `python` / `py`）运行 `<story-long-write>/scripts/select-pending-items.py --directory 追踪/待处理事项 --current-chapter {N} --limit 6 --ordinary-count {普通事项数}`。脚本只用标准库，按数字解析文件名，扫描时只在内存保留最早 6 项，JSON 也最多返回 6 个路径；因此支持千章以上和 Windows，不依赖状态摘要里可能陈旧的索引。`invalid_count > 0` 时停止并报告异常文件名，不猜测其内容。

普通事项就是下一章要办的事，与已到目标章的固定事项同样按当章到期处理。若 JSON 的 `due_overflow` 为 true，说明**普通事项数 + 已到目标章的固定事项数超过 5**；此时向用户报告质量预警和两类数量，**停止且不重写状态摘要**，请用户合并或调整优先级。未超限时，每章都要读取 JSON 返回的精确路径（最多 6 个），按 `record_id` 去重，再按目标章、来源章和序号作数字排序。重建 `## 下一章必做事项` 时，先保留普通事项和已到目标章的固定事项；两类都能全部放下后，才按数字顺序用未满的名额补入未来目标章的固定事项，合计始终最多 5 行。

新增结构性修正、延后兑现等跨章事项时，先运行同一脚本的 `--next-name --target {目标章} --source {来源章}`。分配文件名到写完事项期间只允许主会话操作，其它 agent 不得同时调用 `--next-name`。脚本会创建目录，采用八位章号和四位序号，并同时避开旧版和新版文件名已经使用的序号，绝不覆盖。把事项写入返回路径，格式为 `事项：...`、`目标章节：第N章`、`来源章节：第M章`、`记录编号：{record_id}`；重新读取确认后，才把它写进状态摘要，格式为 `[固定｜目标第N章｜来源第M章｜记录编号={record_id}] 事项`。目录文件是完整依据，**事项进入状态摘要后也不得删除该文件**。新增后再按上文传入普通事项数重跑选择脚本；`due_overflow` 为 true 时同样停止写下一章，不覆盖保存普通事项的旧摘要。

事项结清时，先把结清依据记进本章逐章记录，再删除它的精确文件并确认文件已经不存在；随后重新运行选择脚本、重写并重新读取状态摘要，确保该 `record_id` 已移除、后续事项已按顺序补入。任何一步失败都停止下一章写作。即使在删除文件与重写摘要之间中断，下次也必须先以目录结果为准重建固定事项列表，因此不会把摘要里的旧副本当成仍未结清的事项。每章章末都用脚本返回的 `total`、`earliest_target` 和路径重写 `## 历史记录索引`。这是唯一的额外必读例外，不得读取脚本未返回的文件内容。

**按需加载创作公式**：当写作中需要引用创作公式约束时（如期待感公式、爽点公式、信息差公式），加载 `references/genre-writing-formulas.md`。默认不加载，避免无条件加载 1500+ 行文件浪费 token。

### 状态摘要格式（`追踪/上下文.md` 的统一格式和体积标准）

`追踪/上下文.md` 是**写作状态摘要**：日更每章整份读、每章由主会话整份重写覆盖。全书历史不在这里，在 `追踪/逐章记录/`（每章一个小文件，日更不读，按需 grep）。状态摘要的格式和体积都以本节为准，其它文件只引用，不重复规定。

**顶层 `## ` 区块恰好以下 11 个，不得新建第 12 个**。质量检查记录、参照章使用记录、去 AI 味统计、旧进度、历史决策展开等过程日志一律不进状态摘要，去 `追踪/逐章记录/第{NNN}章.md`。

| 区块 | 上限 | 维护方式 |
|------|------|----------|
| `## 当前位置` | ≤8 行 | 每次完整重写。含卷/本卷主线/章/故事时间/场景/情绪目标/承诺进度/质量预警 |
| `## 文风指纹` | ≤4 行 | 每次完整重写。目标句长带 + 来源，刷新规则见下方「文风召回」 |
| `## 长期约束` | ≤6 行 | **固定保留，不得按写入顺序自动删除**。只有用户明确撤销才能删。第 7 条出现时，先把用户刚确认的规则完整记入本章逐章记录，然后停止下一章写作并请用户指定合并方式；不得删除、擅自合并或写出超限的状态摘要 |
| `## 在场角色` | ≤6 人，每人 1 行 ≤60 字 | 每次完整重写。这里保存**下一章优先角色**：先按下一章细纲的出场顺序取人，再补主角和核心角色，去重后最多 6 人；格式 `角色名｜身份｜当前状态（第N章变化）`。其余角色仍保留在 `追踪/角色状态.md`，本章需要时按「旧信息查找步骤」查询，不因未进入摘要而丢失 |
| `## 活跃伏笔` | ≤8 条 | 每次完整重写。格式 `F0xx｜一句话｜埋第N章｜计划第M章回收｜重要度{高/中/低}`。先从高重要度候选中按逾期优先、计划回收章升序、ID 升序保留最多 2 条；剩余名额再从尚未入选的全部候选中按逾期优先、重要度（高→中→低）、计划回收章升序、ID 升序补足，总数不得超过 8 条。**即使全部是高重要度，也只保留计划回收章最近的 8 条**；移出的条目只离开状态摘要，`追踪/伏笔.md` 中的完整记录不删除 |
| `## 近三章速记` | 最多 3 条，每条 ≤80 字 | 每次完整重写。已有章节不足 3 章时只写实际存在的章节；出现第 4 条时删除最旧一条 |
| `## 下一章必做事项` | ≤5 行 | 每次完整重写。默认只放下一章要处理的一次性任务；跨多章才能结清的事项同时保存在 `追踪/待处理事项/`，摘要行写成 `[固定｜目标第N章｜来源第M章｜记录编号={record_id}] 事项`。旧项目的固定事项没有来源章时，首次重写用迁移时的当前章作为来源并在逐章记录注明，再为它创建单项文件和记录编号。普通事项与已到目标章的固定事项必须全部保留；未超限时才用未满名额按目标章、来源章和序号补入未来目标章的固定事项。前两类合计超过 5 时不重写摘要并停止；目录中的完整记录不得因摘要达到 5 行而删除 |
| `## 累计待处理项` | ≤5 行 | **每次写入完整数值，不追加**。格式 `key：值（自第N章）`，如「对话占比连续偏低：4 批（自第29章）」。计数只增，下降必须在 `追踪/逐章记录/` 有对应的结清记录 |
| `## 十章概要` | ≤4 行 | 只保留最近 4 行，超过时删除最早一行（完整内容在 追踪/阶段摘要.md）。Step 4 每写满 10 章更新一行，用它保留较长时期的剧情信息 |
| `## 待办` | ≤5 行 | 每次完整重写 |
| `## 历史记录索引` | ≤6 行 | 每次完整重写。列出 `追踪/` 下各历史记录文件或目录的用途与当前行数/文件数；`追踪/待处理事项/` 有文件时必须在一行内列出数量、最早目标章和最早文件路径 |

**体积**：目标 8192 字节，硬上限 12288 字节。**条数上限和 12288 字节硬上限优先**；“固定”或“高重要度”表示不得丢失内容，不表示可以让状态摘要超限。超出时按下方规则把内容留在完整记录或专用待处理文件中，状态摘要本身仍必须合规。

**超出上限时的处理**：

- **规定区块以外的整块**（模型自造的「本轮质量检查」「参照章使用记录」这类）：内容还没进任何地方，**先写进本章 `追踪/逐章记录/第{NNN}章.md`，再从状态摘要删掉**。搬运，不是删除。
- **一般条目超限**（近三章速记第 4 条等）：只从状态摘要移出；完整内容已在对应的 `追踪/逐章记录/` 中，不删除源记录。
- **活跃伏笔超过 8 条**：按上表的固定排序取前 8 条；其余只从状态摘要移出，仍保留在 `追踪/伏笔.md`，需要时按「旧信息查找步骤」取回。
- **下一章事项超过 5 项**：先用“普通事项数 + 已到目标章的固定事项数”判断；超限就保留旧摘要并停止，不得把普通事项挤出。未到目标章的固定事项只在仍有名额时显示。所有固定事项始终各自保存在 `追踪/待处理事项/`；每章只读取脚本返回的最多 6 个小文件，不会随目录文件数增加而通读更多内容。事项结清时按上方“先记结清依据，再删除精确文件，最后重写并核对摘要”的顺序执行。
- **长期约束超过 6 条，或保护内容单独就会超过 12288 字节**：完整内容先写入本章逐章记录，然后停止下一章写作并请用户决定如何合并；不得丢失规则，也不得写出超限状态摘要。

例外：`## 累计待处理项` 是把各章的变化数相加后得到的总数，`追踪/逐章记录/` 里只有每章变化数、没有累计值——它一旦被删除，只能读遍全部逐章记录重新求和才能复原。所以它必须保持 ≤5 行，计数只能增加，不得从状态摘要中删除；如果需要第 6 种计数，先合并为更高层的同类计数，无法无损合并时按上述规则停止并请用户决定。

状态摘要中每个区块的维护方式必须写在区块注释里（`<!-- 每次完整重写 -->` / `<!-- 只保留最近 N 条，超过时删除最旧一条 -->` / `<!-- 固定保留，不得删除 -->`），这样每章读状态摘要时规则一并被读到。

**不合规状态摘要的处置**：读到的状态摘要超过 12288 字节或含规定以外的区块时，不要 Read 全文分析、也不要逐块删。按顺序：

1. 用可用的 Python 命令运行 `<story-long-write>/scripts/extract-context-sections.py prepare 追踪/上下文.md 追踪/逐章记录/_旧状态摘要关键区块_截至第{N}章.md 追踪/逐章记录/_旧上下文_截至第{N}章.md`。脚本会先创建目标目录，把完整旧文件原样复制到不会覆盖既有内容的归档，再提取现行 11 个规定区块和旧版的「最近决策」「待处理线索」；每个区块都从标题行**一直取到下一个顶层 `## ` 标题之前**，不会因固定行数或末尾长日志而截断。JSON 同时返回尾部最多 8000 字节的 `tail`，不依赖平台专属的文件尾部命令。脚本还会写入 `追踪/.上下文迁移.json`，中断后使用同一命令即可核对并继续，不得覆盖内容不同的归档。
2. 核对 JSON 返回的区块名、摘要副本字节数和归档路径；用 `Read` 检查两个输出文件的首尾，确认规定区块和完整旧文件都已保存。受保护区块单独超过 12288 字节时，停下请用户决定如何无损合并。长期有效的规则归入新摘要 `## 长期约束`，累计数值原样带入，仍开放的线索归入 `## 活跃伏笔` 或 `## 下一章必做事项`；其它规定区块也逐项保留有效内容，不能只依赖尾部文字。
3. 用第 1、2 步保存的内容 + JSON 的 `tail` + 本章细纲 + 最近 3 章正文，先 `Write` 到 `追踪/上下文.md.new`，不要改动原来的 `追踪/上下文.md`。重新 `Read` 候选文件，确认不超过 12288 字节、11 个规定区块恰好各出现一次且顺序正确。
4. 运行 `<story-long-write>/scripts/extract-context-sections.py install 追踪/上下文.md 追踪/上下文.md.new 追踪/逐章记录/_旧状态摘要关键区块_截至第{N}章.md 追踪/逐章记录/_旧上下文_截至第{N}章.md`。脚本只有在原文件、归档、副本和候选文件全部核对通过后，才一次替换正式状态摘要并清除迁移标记；任一检查失败时原文件保持不变。中断后若标记仍在，先重跑本步或第 1 步恢复，不走普通的新建摘要流程。`追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md` 不动。

**与项目 rules 的关系**：部分项目的 `.claude/rules/story-consistency.md` 写有「设定决策记录到 上下文.md 的最近决策部分」。以本节为准：永久生效的进 `## 长期约束`；影响后续 3 章内的，先按“跨章事项检查”创建单项文件，再写进 `## 下一章必做事项`；其余记进本章 `追踪/逐章记录/第{NNN}章.md` 的「决策」行，不新建 `## 最近决策`。

**卷级总览**不进状态摘要；状态摘要的 `## 十章概要` 只保留最近 4 行，完整内容在 Step 4 的 `追踪/阶段摘要.md`。

> **首次日更兜底**：如果 `追踪/` 目录下的文件全部为空或不存在（刚完成 Phase 3 但未日更过），额外加载 `大纲/卷纲_第{N}卷.md` 和最新一章正文来重建上下文。

> **确定下一章编号 N**：从状态摘要 `## 当前位置` 的「章」字段读取，+1。如果文件不存在或该字段缺失，扫描 `正文/` 目录中编号最大的章节 +1。

确定本轮写作范围后直接进入 Step 2，不做"是否继续"式确认。K 默认 2-3 章；用户明确说"只写1章"/"日更3章"/"逐章确认"时按用户要求调整。用户给出 N>3 时，本轮只写前 3 章并在 Step 4 进度摘要提示"剩余章节下轮继续"。仅在章节号冲突、细纲缺失、请求范围超过已有细纲、用户要求会改变大纲/追踪，或存在其他会导致写错的阻塞信息时暂停确认。

## Step 2：串行批量写作

一次加载多章细纲，但**必须在主会话内串行逐章写作**：不得把多章同时交给多个子代理并发写。长篇章节依赖上一章正文和追踪文件，并发会导致上下文断裂、追踪覆盖和标题去重失效。

**批量 continuation 规则**：进入本 Step 后，"继续"/"续写"/"日更"只表示继续当前日更批量流程。不得把这些词解释为跳过「状态筛选」或「对标模块/节奏/题材卡/文风召回」的直接正文续写；也不得在每章之间重复询问是否继续，除非用户明确要求逐章确认或出现阻塞。到达本轮 K（最多 3 章）后必须进入 Step 3/4 收尾并停止，不能因为仍有后续细纲就继续写下一批。

1. **读取写作计划**：写作计划按 **卷契约 → 当前剧情单元 → 章节细纲** 的顺序确定；已写内容仍以正文与 `追踪/` 文件为准。先从 `大纲/卷纲_第X卷.md` 读取卷契约、当前剧情单元（单元ID/位置）、单元情绪引擎、本卷主推线/战果与终局底牌边界，再加载本次要写的 2-3 章细纲。旧版卷纲缺少卷契约/剧情单元卡不阻塞日更：本轮在内存推断，结论精简为一行写进状态摘要 `## 当前位置` 的「本卷主线」，完整判断过程记进本章 `追踪/逐章记录/第{NNN}章.md`；仅在明确补纲/改纲时回写卷纲；未知字段写 `[待补充]`；绝不自动修改已锁定卷纲。新版细纲优先读取「阶段位置」「本章结构公式」「本章禁止提前释放」「内容概括（起因/发展/转折/高潮/结尾）」「情节安排（主线/辅线/事件线/感情线/逻辑线）」「人物关系和出场顺序」「情节细化」「结尾设定和钩子」；旧版细纲缺这些字段不阻塞，回退到核心事件、情节点序列、目标情绪、章首/章尾钩子、字数目标。旧细纲有字数目标但无逐点预算时，写后定位欠账先按功能标签派生临时预算（爽点/打脸/反转=密、过场/赶路=疏）再分配，不凭感觉挤牙膏。
   - **批次定位与阶段约束**：写本批前先从 `大纲/大纲.md`、对应 `大纲/卷纲_第X卷.md` 和本批细纲提取：当前章节区间属于哪个阶段、本批推进目标、本批可释放的信息、本批严禁提前释放的信息、章尾钩子不能越过的边界。必须按终局储备确认本批主推线与战果，别动用本阶段还不该解锁的终局底牌（多线齐涨的战果允许）；行动成本可无，不硬造代价。没有明确阶段总览时，仅为本轮按卷纲和已写进度临时归纳；本轮明确补纲/改纲时才回写，否则记进本章 `追踪/逐章记录/第{NNN}章.md`，只把本批不得提前写出的信息精简为一行写进状态摘要 `## 下一章必做事项`；锁定大纲/卷纲绝不自动修改。
   - **阶段进度自检**：每批写完或补完细纲后检查是否超前、拖慢或偏离阶段节奏；若偏离，把补偿方案（例如下批加快冲突、延后真相、补一处关系回收）写进状态摘要 `## 下一章必做事项`，完整判断记进本章 `追踪/逐章记录/第{NNN}章.md`；不得通过提前泄露后期信息强行提速。
2. **逐章执行**（以下每步在每章循环内执行）：
   - 读细纲 → 按需加载角色设定
   - **标题预检**：扫描既有章节标题；如本章标题同名或明显重复，先按本章核心事件改名，并同步细纲标题与正文文件名
   - **上一章欠账检查**：写本章正文前，确认上一章正文无未清 blocking 毒句式欠账（写前 hook 会自动拦；hook 不可用时对上一章跑 `node scripts/check-ai-patterns.js --check --fail-on=blocking`）；有欠账先清完再写本章，除非上一章标了 `<!-- 去味:跳过 -->`（用户显式豁免）
   - **状态筛选**：每章开始前必须确认以下三项通常来源已经在本轮 workflow 中读取或刚更新：本章细纲、上一章正文（或上一章刚写入的正文）、`追踪/上下文.md`（状态摘要）。"已加载"只指本轮 workflow 内实际读取/更新过的文件，不得用未标明来源的聊天记忆替代。角色最新状态从状态摘要 `## 在场角色` 取，待回收/推进伏笔从状态摘要 `## 活跃伏笔` 取；跨章事项以本章刚运行的选择脚本 JSON 为准，只读取其返回的精确路径，最多 6 个，按 `record_id` 去重后重建摘要中的固定事项。状态摘要里没有的其他内容按下方「旧信息查找步骤」按需查询，**除上述少量单项文件外，不得 Read `追踪/伏笔.md`、`追踪/时间线.md`、`追踪/角色状态.md`、`追踪/逐章记录/` 全文或通读 `追踪/待处理事项/`**——那会让每章的读取量重新涨回去。细纲不存在时仍按下方补建流程处理，不允许直接写正文
   - **久别角色交叉检查**：本章细纲列出的角色名，若不在状态摘要 `## 在场角色` 里，本章必须走一次「旧信息查找步骤」的 `character_status` 按需查询（不占下方查询次数限制配额），结果写回 `## 在场角色`。`设定/角色/{名}.md` 只有 Phase 3 的原始人设、日更从不回写剧情变化（见 [Phase 3：大纲搭建](../SKILL.md#phase-3大纲搭建) 的「细纲后设定补全」），拿它当久别角色的当前状态会写崩人设
   - **对标模块/节奏/题材卡/文风召回**：
     - 调 story-explorer 的 `benchmark_style_load` query_type（输入：项目目录 + 本章目标情绪 + 本章爽点类型 + 本章目标字数）一次性拿到：`{style_profile_path, style_profile_summary, selected_emotion_module, rhythm_reference, module_source_path, rhythm_source_path, matched_chapter_K, matched_chapter_techniques, anchor_excerpts, gaps}`
     - **题材正文提示卡召回**：主会话优先读 `设定/题材正文提示卡.md`；缺失则先读 `设定/题材定位.md` + `references/genre-prose-cards.md` 索引，按主题材精确匹配后只读取 `references/genre-prose-cards/{题材}.md` 单卡（如 都市脑洞 / 豪门总裁 / 年代 / 双男主；低置信卡必须在意图确认标注低置信，并要求同题材对标校准），无命中再读 `references/style-genre-modules.md` 通用流派模块。跨题材时主题材抽 3-5 条、辅题材抽 1-2 条，生成 `genre_prose_card`（题材边界、核心逻辑、读者期待、核心爽点/情绪、节奏密度、场景颗粒、禁止漂移、本章取舍、卡片置信度）。题材卡必须进入 narrative-writer prompt，但只传短摘要，并说明卡片只供内部题材校准、正文里不得出现卡片文字或合规自评
     - **自定义文风覆盖（先于下列 gaps 判定）**：主会话直接读 `设定/文风.md`（不经 explorer），含实质内容（去空白 ≥200 字，或含 句长 / 标点 / 对话 / 锚点 / 笔调 小节且小节内有可执行约束：比例 / 例句 / 禁止或偏好描述）则置 `custom_style=true`——它作权威风格基**取代** `style_profile_path` 喂给 narrative-writer（句长 / 标点 / 潜台词 / 情绪交替），对标 / 拆文 `style_profile_path` 降级为参考（原文锚点 + 句长分布数值兜底）。空 / 仅空白 / 仅标题 / 占位 stub（待办 / 待补充 / ___）视为不存在。仅接管风格，**不豁免情绪 / 节奏轴**。
     - 若 `gaps.no_benchmark: true` → `custom_style` 为真则进入「自定义文风模式」（用 `设定/文风.md` 写作；无对标可召回，情绪 / 节奏目标改从本书细纲「目标情绪」、卷纲、`设定/题材定位.md` 等内部材料取，`selected_emotion_module` / `rhythm_reference` 记为「无」，不声称从对标召回）；否则跳过文风召回，在「意图确认」标记"无对标参考"
     - 若 `gaps.missing_primary_contract: true` → 停止本章准备，按 `repair_action` 提示重跑 `/story-long-analyze` Stage 3+ 或重新 `/story-import`；不得进入 narrative-writer（情绪 / 节奏轴独立于文风轴，**自定义文风模式不豁免此停止**——补 `剧情/情绪模块.md` / `剧情/节奏.md`，而非写 `设定/文风.md`）
     - 若 `gaps.conflict` 或 `gaps.module_rhythm_conflict: true` → 意图确认必须说明冲突并按 `剧情/情绪模块.md` / `剧情/节奏.md` 的权威优先级执行；不得让 `文风.md` 覆盖情绪/节奏目标
     - 若 `gaps.profile_missing: true` → `custom_style` 为真则进入自定义文风模式继续；否则按上文 fail-fast 流程停止
     - 若 `gaps.profile_degenerate: true`（对标文风不可用） → `custom_style` 为真则用 `设定/文风.md` 写作；否则跳过文风、回到默认 Gates 写作
     - 若 `gaps.tone_match_failed: true` → 仅用整书文风写作，不喂 matched_chapter
     - 否则原样传给 `style_profile_path`、`style_profile_summary`、`selected_emotion_module`、`rhythm_reference`、`module_source_path`、`rhythm_source_path`、`matched_chapter_K`、`matched_chapter_techniques`、`anchor_excerpts` 和 `genre_prose_card` 给 Step 2 末尾的 narrative-writer spawn prompt；其中 `selected_emotion_module` 必须进入情绪目标，`rhythm_reference` 必须进入节奏/爆发安排，`genre_prose_card` 必须进入题材取舍，`matched_chapter_techniques` 必须进入「文风召回指令」。写前准备记录必须保留 `gaps` 原值，尤其 `gaps.module_missing`、`gaps.rhythm_missing`、`gaps.conflict`、`gaps.matched_deep_dive_missing`；若 `matched_deep_dive_missing` 为 true，文风召回指令中明确写“同章深度拆解缺失，已回退黄金三章/文风技巧”，不得在后续报告中反转为 false
     - **无 story-explorer 时直接执行**：主会话手动按对标书路径查找，先读 `剧情/情绪模块.md` 选 `selected_emotion_module`，再读 `剧情/节奏.md` 选 `rhythm_reference`，读 `设定/题材正文提示卡.md` 或按 `genre-prose-cards.md` 索引 + 单题材卡优先即时生成 `genre_prose_card`，先读 `设定/文风.md`（含实质内容则 `custom_style=true`、作权威风格基，对标 `文风.md` 降为参考 / 句长兜底）、再读对标 `文风.md` + grep `章节/*_摘要.md` 的「基调」字段找匹配章，然后读对应 `第K章_摘要.md`；如 `第K章_深度拆解.md` 不存在，改读 `第1-3章_深度拆解.md` 中与本章基调最接近的一章。模块或节奏文件缺失时设置 `missing_primary_contract` 并停止修复
   - **意图确认**：从细纲「目标情绪」字段确认本章情绪目标，综合状态筛选结果 + `selected_emotion_module` + `rhythm_reference` + `genre_prose_card` + 文风召回输出，用一句话写本章意图（情绪+节奏+模块+题材取舍+文风指令）。意图必须表达“**情绪前状态 → 触发 → 后状态**”，不得只写情绪标签，并指明本章推进单元情绪引擎的哪一环。意图确认必须消费主角代理权、当前剧情单元的主角目标/关键选择、本单元主推线/战果、终局底牌边界与收益归属。仅当新承载对象、关键转折或高潮进入时，运行 emotional-methods.md 的“合理性五问”；不要让每段填表。若新版细纲存在，意图确认必须显式带入：阶段位置和禁止提前释放决定本章边界，结构公式决定推进骨架，内容概括决定起承转合，情节安排决定主线/辅线/事件线/感情线/逻辑线的取舍，人物关系和出场顺序决定镜头进入顺序，情节细化决定行动成本（可无）/收益归属，结尾设定和钩子决定章尾承接——但这些字段只界定本章"要发生什么"，不规定正文的形状：不得把情节点逐条按序各扩成一段、不得把"谁做了什么"的概括语原样搬进叙述、五段式不是五个顺写的段块，可自由合并/穿插/重排情节点，把每个点演成场景（见 writing-craft.md「从细纲到正文」）；并落实四条写作要求——① 发展/转折=爽点(高潮)的铺垫蓄势，爽点出手前先铺可指认的危机/期待（plot-emotion-system 倒推法，不铺=空洞）；② 装逼/打脸/揭露章把 视角/信息差 经 出场顺序 里的在场配角放大成差异化反应（plot-core-methods 信息差×人际×情绪/集体震惊）；③ 对话声线基线随基调——高压/生死/悲痛节拍→搞笑担当/轻快配角声线让位、信息型配角不当科普嘴、对话逐句承接对方情绪；④ **细纲优先边界**——只展开本章细纲已有事件/人物/伏笔/钩子，不自造新主线、新角色、新反转，不提前写后续章剧情。写进本章意图、生成时即按基调收敛。按权威文件的因果权 + 结算权与“关键节点四问”确认期待所有权：配角可执行局部动作，不要求主角亲自动手，但不得无声夺走已承诺的高光/收益；若被配角、机构或偶然性捕获且没有可见交换，标记 `protagonist_agency_risk`，先修复细纲/卷纲再进正文。自愿让渡是否亮红灯、战略性让步如何算，按权威文件判，不在本步展开。例：「快节奏打脸——起因=账单暴露，逻辑线=发现→逼问→反证→公开代价；复现 M03‘信息差反杀’的读者期待，按都市世情题材卡落到账单/转账/旁人反应，关键信息先压后爆，爆发后用一段冷却承接下一钩子；标点照文风里的停顿节奏、对话潜台词用问非所答；剧情边界=不得新增账单之外的新敌人或提前解决下一章钩子。」
   - 写正文 → **字数验证（优先 Python 字符统计，`wc -m` 仅作 Unix 备选，< 目标90%则对照情节点字数预算定位欠账密点、一次性重写到配额，不挤牙膏反复回炉；只能扩写细纲内已有情节点，若现有细纲不足以达标则停止并输出 `outline_underfilled` 欠账点；> 章目标×1.1 则压过场/合并疏点收敛；90% 是放行下限非目标，理想落在 [章目标, 章目标×1.1]）** → 检查钩子/爽点 → **正文元信息扫描** → 禁用词扫描（含 SKILL Phase 4 步骤 11 的最毒句式速查；写后 hook 推回的毒句式命中当轮清零，不得留到批末）
     - **正文元信息扫描**：标题行以外不得出现 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者`。这些词属于写作/工程元信息，必须改成角色当下能感知的事件锚点或相对时间；例如“比第一章那三秒开火更疼”改成“比那三秒开火更疼”。只有角色在故事世界内真实阅读/讨论“第X章”文本，或真实身为作者/读者并谈论读者身份时例外。
   - 每章写完后**立即分两步更新追踪文件**，顺序不可颠倒：

     **第一段：记录本章**。用 `Write` 新建 `追踪/逐章记录/第{NNN}章.md`（三位补零，如 `第031章.md`；章号过千按实际位数），这份文件完整记录本章内容，后续以它为准；必须长期保留，日更不读取：

     ```markdown
     # 第 {N} 章 · {章名}
     单元ID：{Lx-y}｜漂移：{aligned|adaptive|structural}
     计划节拍：{原计划}
     实际结果：{实际写成什么}
     收益变化：{兑现增加/延期/转移及归属}
     主推线/战果：{本章推进线}｜承诺进度：{期待债进度}
     下一章必做事项：{下一章必须完成的事项}
     跨章事项：{新增/更新/结清的 record_id 与依据；无则写“无”}
     伏笔：{新埋 F0xx 内容/计划回收章}｜{回收 F0xx 方式=x 效果=x}
     时间线：{故事时间}｜{事件}
     角色：{角色}｜{维度 身份/能力/关系/形象}｜{本章后的完整当前值；关系写成 与对象：当前关系；每个变化维度或关系对象单独一行}
     历史记录待追加行：{逐行写明目标文件和完整 ASCII 表格行；伏笔、时间线、角色状态没有变化时写“无”}
     - 伏笔.md｜| F0xx | 内容 | 埋设章 | 预计回收章 | 状态 | 重要度 |
     - 时间线.md｜| 第N章 | 故事时间 | 事件 | 涉及角色 | 与主线关系 |
     - 角色状态.md｜| 第N章 | 角色 | 维度 | 本章后的完整当前值 |
     决策：{本章用户确认的规则或设定决定，标 [长期] 或 [一次性]}
     过程日志：{去 AI 味删改量、质检结论、参照章等}
     待处理项：{本章新增或递增的项目}｜结清：{本章结清的项目，状态摘要 ## 累计待处理项 下降必须对应这里的一条}
     ```

     写完 `追踪/逐章记录/第{NNN}章.md` 后，再把记录行 `>>` 追加进三个历史记录文件。**追加位置固定是各文件末尾的 `## 逐章更新记录` 小节**——它必须是文件最后一个小节，这样 `>>` 追加的行会落在该小节中。该小节不存在时（旧项目）先在文件末尾补小节标题和该文件对应的表头，再追加数据行；若发现它不在文件末尾（被手工编辑过），也在文件末尾重新补标题和表头。没有这个小节就直接 `>>` 的后果：三个模板原本的最后一张表分别是「过期伏笔」「待确认（时间线疑点）」和最后一个角色小节，新伏笔会被记成过期、角色变更会记到错的角色名下。

     格式必须是 ASCII 竖线表格行，与各文件原有表列序一致：

     - `追踪/伏笔.md`：`| F0xx | 内容 | 埋设章 | 预计回收章 | 状态 | 重要度 |` —— **六列顺序不能动**，SessionStart 的过期伏笔告警按第 6 列判状态，列错位等于把这条告警废掉
     - `追踪/时间线.md`：`| 第N章 | 故事时间 | 事件 | 涉及角色 | 与主线关系 |`
     - `追踪/角色状态.md`：`| 第N章 | 角色 | 维度{身份/能力/关系/形象} | 当前值 |`。身份、能力、形象必须写本章后的完整当前值，不写“提升了”“改变了”这类无法还原现状的笼统变化；关系行必须用 `与{对象}：{当前关系}`，每个关系对象单独一行

     这三个文件**只用 shell 追加重定向，不得用 Read / Edit / MultiEdit**——Edit 要求先 Read 全文，对已长到上百 KB 的历史记录文件会让每章的读取量重新涨回去。追加后用 `tail` 配合精确固定字符串匹配，**逐条核对刚追加的记录**是否落在正确文件且列数正确；失败时重试一次。重试后仍缺失时，在本章逐章记录和状态摘要 `## 当前位置` 的“质量预警”写明缺失文件与待补行，并**停止写下一章**。恢复时从本章逐章记录的「历史记录待追加行」原样重做缺失追加，核对成功后清除质量预警；不得静默跳过，也不得声称其他 skill 会自动重建。

     **第二段：重写状态摘要**。`Write` 整份覆盖 `追踪/上下文.md`（本轮 Step 1 已读过它，≤12KB，覆盖不需再读），按上方「状态摘要格式」的 11 个区块与条数上限重建。一般条目移出状态摘要时，完整内容已在本章或更早的逐章记录中；活跃伏笔必须留在 `追踪/伏笔.md`，跨章事项必须始终有对应的 `追踪/待处理事项/{record_id}.md`，不得直接丢弃。

     重建前先确认手上有上一版的完整内容：**本轮发生过 compaction，或不确定上一版某个区块写了什么，就先 `Read` 一次状态摘要再覆盖**——它 ≤12KB，重读一次的成本远小于把 `## 长期约束` 或 `## 累计待处理项` 凭残缺记忆写没了。

     重建时逐个区块保留上一版内容，只改本章真正变了的：`## 长期约束` 原样保留（除非用户本章明确撤销）；`## 累计待处理项` 把上一版的计数读出来，加上本章的变化数后再写回，不要从零重记；`## 文风指纹` 仅当「来源」与本次权威风格基不一致（自定义文风模式下应为 `设定/文风.md`）时，用 narrative-writer 报回的本章句长分布刷新并写明来源，来源一致就原样保留。**默认保留，删除要有理由**——不确定某条该不该留就留着，它下一章还会被这条规则再判一次。

     状态摘要**只能由主会话写入**。narrative-writer 只写正文并在返回末行报句长分布；逐章记录与状态摘要所需的其余字段，主会话从刚写入文件的正文和本章细纲中提取，不由 agent 写 `追踪/`。
   - **质检提示**（可选）：本章写作完成。如需一致性检查，运行 `/story-review lean`。批量写作模式跳过此步骤，全部写完后再统一审查。
3. **不中断但不并发**：一章写完不问用户，直接写下一章（除非用户要求逐章确认）；下一章必须读取上一章刚写入的正文和追踪更新后再开始。

**资料研究（按需）**：如果写作中遇到需要查证的外部事实（历史年代、地理方位、职业细节等），暂停写作，spawn `story-researcher` agent 搜索并输出到 `参考资料/` 目录。研究完成后再继续写作。

### 旧信息查找步骤

状态摘要里没有、但本章确实需要的旧信息（20 章前埋的伏笔、久别角色的当前状态、某个时间锚点），按以下顺序查找，**每一步的读取量都有上限**。不允许因为"查着方便"退化成读历史记录文件全文。

| 级别 | 手段 | 成本 |
|------|------|------|
| 1 | 状态摘要里已有 → 直接用 | 0 |
| 2 | `Agent(subagent_type: "story-explorer", ...)`，query_type 取 `foreshadow_status` / `character_status` / `timeline` | 子代理读取全文，主会话只接收按固定字段整理的摘要 |
| 3 | explorer 不可用 → `grep -R -n --include='*.md' "F007" 追踪/伏笔.md 追踪/逐章记录/ 2>/dev/null \| tail -5`，递归查找逐章记录并只返回最后 5 条匹配行 | 只读取匹配行 |
| 4 | 仍不够 → `Read` 埋设章那一章正文（单章 ≤4KB） | 单章 |
| 5 | 完整读取所有历史记录文件 | **日更禁止**。只在 `/story-review` 或用户明确说"全面检查伏笔 / 通读追踪"时 |

步骤 2 的关键：读大文件这件事发生在子代理里，不进主会话上下文。

**查询次数限制**：单章执行步骤 2 和步骤 3 合计超过 3 次，说明细纲没写清本章要回收什么。这时不要硬停——一次性 spawn story-explorer 做一次查询多项（读取仍在子代理上下文，每章读取量不受影响），并在 Step 4 汇报「本章集中查询了多项旧信息，细纲建议写清回收项」。

查询结果通常不写入状态摘要；只有该条在本章之后仍然有效时，才写入 `## 活跃伏笔`，或在该角色属于下一章优先角色时写入 `## 在场角色`。角色超过 6 人时按状态摘要的固定筛选顺序取舍，未入选结果只留在本轮工作上下文和 `追踪/角色状态.md`，不得为了写回而挤掉下一章更优先的角色。

## Step 3：质量检查

批量写作结束后，对本次所有新写章节执行 Phase 5 质量检查（至少包含）：

1. **禁用词扫描**：对照 `references/banned-words.md`，一级词命中即替换
2. **标题去重检查**：汇总本轮新写章节与既有标题；发现同名或明显重复时，回到对应细纲和正文文件统一重命名
3. **正文元信息扫描**：检查标题行以外是否混入 `第[一二三四五六七八九十百千万两0-9]+章|上一章|上章|前一章|本章|这一章|前文|后文|伏笔|细纲|读者` 这类写作工程词，命中即改成场景内表达；故事内真实阅读/讨论“第X章”或真实读者身份语境除外
4. **钩子检查**：每章章尾是否有往下看的理由（低压/过场章弱钩子或阶段目标即可，不强求强钩子，按细纲章节定位；见 references/outline-structure-theory.md「章节定位与张弛」）；如新版细纲有「结尾设定和钩子」，检查结尾是否落在具体动作/画面/悬念上（"收束状态"是规划口径，不是要写进正文的状态总结句）、留下未解决问题和下一章推动力
5. **契约与细纲双向核对**：先按 `reader-contract-and-progression.md` 检查读者契约、因果权 + 结算权、关键节点四问、期待所有权、期待债偿还、终局储备（透支两问）；章级推进按权威文件七类状态分档（快节奏保留可见事件/爽点下限），相对本书题材与对标判断；高潮后允许短暂低压和小而可见的收益/奖励。新地图/机构/能力/敌人/谜团须检查换书债；履约爽文/能力幻想另查主角是否反复以可避免的无能制造灾难再由他人收拾。再对照细纲核对正文有没有按细纲写到。新版细纲存在时，核对正文是否消费了内容概括五段式、情节安排多线、人物关系变化/出场顺序、行动成本（可无）/收益归属；并加三条写作要求 兑现核对（不达标→修复）：① 爽点出手前是否有可指认的危机/期待铺垫段落？指不出=空洞 → 回 Step 2 补铺垫情节点（plot-emotion-system 倒推法）；② 装逼/打脸/揭露章是否写出在场配角差异化反应（集体震惊/各异），还是只写主角动作？没有 → 补在场配角反应（plot-core-methods）；③ 详略是否按目的词（爽点/卖点点展开、过渡点带过、信息密度交替），还是均匀注水？均匀 → 删过渡、扩爽点点。旧版细纲只核对核心事件、目标情绪、章首/章尾钩子和字数目标
6. **只检查本轮变化的伏笔**：确认本批新增、推进或回收的伏笔已经追加到 `追踪/伏笔.md` 的 `## 逐章更新记录`（`tail -20 追踪/伏笔.md` 核对即可，不读全文、不原地改）；不得在日更流程中通读所有 session 或扫描全部正文做全量伏笔审查。只有执行 `/story-review` 或用户明确要求“全面检查伏笔”时，才检查全书伏笔
7. **确定性收尾**：主会话对本批实际落盘正文运行 `node scripts/check-ai-patterns.js --check --fail-on=blocking 正文/第XXX章_*.md`；blocking 先改正文并复扫，advisory 只作读感提示，功能性写法标 `[需复核]`。
   再运行 `node scripts/normalize-punctuation.js 正文/第XXX章_*.md`（默认 `--quote-mode keep`）清理无功能省略号、破折号、双连字符和独立分隔线。narrative-writer agent 不运行这些脚本。
   - **退化防护**：再跑 `node scripts/check-degeneration.js --check 正文/第XXX章_*.md`。blocking 只重写受影响章节，最多 2 次；仍失败就报告证据让用户定夺。advisory 先看例外，确属工程词泄漏或退化再改。

> 完整检查清单见 [Phase 5：质量检查](../SKILL.md#phase-5质量检查)。

## Step 4：批末收尾

本步通常不再改状态摘要；只有第 3 项生成新的十章概要时，才把该行同步进 `## 十章概要`。做三件事：

1. **状态摘要合规自查**：`wc -c 追踪/上下文.md` ≤12288；顶层 `## ` 恰好是「状态摘要格式」规定的 11 个、无重复标题；各区块条数不超上限；`## 活跃伏笔` 按计划回收章升序。任一不合规，按「超出上限时的处理」移进本章 `追踪/逐章记录/第{NNN}章.md` 后重写状态摘要。
2. **逐章记录自查**：本批每一章都有对应的 `追踪/逐章记录/第{NNN}章.md`。缺哪章补哪章——状态摘要每章都会重写，缺一章逐章记录才是真丢历史。
3. **长周期概要**：章号能被 10 整除或到达卷末时，先 `Read` 这个平时不读的小文件；文件不存在时按 artifact-protocols 的完整模板新建。十章概要必须用 `Edit` 插入或更新到 **`## 十章概要` 表内**（`章节范围 | 已写核心事件 | 角色状态变化`）：先算本组起始章 `S=floor((N-1)/10)*10+1`，若已有**起始章相同但不足十章的旧行**（常见于导入停在组中间），把它扩展并改写为 `第S-N章`，不得再新增一条重叠记录。卷末总览插入或更新到 `## 卷级总览` 表内（`卷名 | 已写主线进展 | 关键转折`）；**不得用 `>>` 把十章概要追加到文件末尾**，否则它会落进最后的卷级总览区块。生成十章概要时，再把同一行写进状态摘要 `## 十章概要`；状态摘要里相同起始章的旧行也直接替换，最后只保留最近 4 行。

然后向用户口头汇报本批完成情况（章数、字数、漂移、下一批建议），不另存为文件。

---

> **漂移处理**：aligned = 按计划推进；adaptive = 细节适配但不改契约；structural 漂移 / 结构性漂移 = 正文已经改变卷契约、单元承诺、推进线或兑现归属，必须修正文或重规划未来章节细纲，不能只在逐章记录里备注。未解决的 structural 漂移按“跨章事项检查”先创建单项文件，再写入状态摘要 `## 下一章必做事项`；修掉后按事项结清顺序删除。`## 下一章必做事项` 合计不得超过 5 行，完整固定事项以目录文件为准。

## 细纲缺失补建流程

当检测到细纲不存在时，不能跳过。按以下步骤补建：

1. 加载 `大纲/卷纲_第{N}卷.md`（本章对应的事件规划），读取本章所属剧情单元卡；剧情单元卡含「对标剧情参照」时加读其指向的剧情单元文件（1 个），以其「结构分布」对应位置作本章功能参照；若本章起整个剧情单元均无细纲，建议按 outline-structure-theory.md「按剧情批出细纲」整批补建而非单章补。参照缺失、旧版卷纲无此字段一律不阻塞，按原流程继续
2. 加载本章涉及的 `设定/角色/{角色名}.md`（角色状态）
3. 读取最新一章正文（情节衔接）
4. 按 SKILL.md Phase 3 的新版细纲模板补建本章细纲，补齐阶段位置、本章结构公式、本章禁止提前释放、内容概括、情节安排、人物关系/出场顺序、情节细化、结尾设定；无法从卷纲/正文/设定确认的字段写 `[待补充]`，不杜撰
5. 补建完成后继续 Step 2 写作

## 常见问题

| 问题 | 处理 |
|------|------|
| 细纲不存在 | 执行上方"细纲缺失补建流程" |
| 细纲缺当前蓝图字段 | 旧版细纲不阻塞日更：按 Step 2 第 1 步的回退字段消费，仅本轮明确补纲/改纲时回填；新建/补建细纲必须按当前模板齐全，未知项写 `[待补充]` |
| 追踪文件为空 | 正常继续，写作中逐步填充 |
| 用户要求改大纲 | 提醒"改大纲会影响后续细纲"，确认后修改，标记受影响的细纲 |
| 写到卷末 | 提示用户"当前卷已完成，是否开新卷？" |
| 用户中断批量写作 | 保存当前章节，已更新追踪文件，下次从断点继续 |
