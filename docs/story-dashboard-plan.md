# Story Dashboard：产品、视觉与开发计划

## 1. 目标

为 oh-story 提供一个随 skill 分发的本地工作台。作者在写作工作区执行
`/story dashboard`（Codex 用 `$story dashboard`）后，能在浏览器里：

1. 查看项目根 `拆文库/` 下的拆文资产；
2. 查看长篇、短篇等写作项目的文件树；
3. 打开常见文本文件并做轻量编辑、保存或确认后删除；
4. 搜索文件名，快速在素材和稿件之间切换；
5. 不安装前端框架、不把写作内容上传到远端。

本期不是完整 IDE：不做多人协作、富文本、版本历史、AI 改写、文件移动、目录删除、
批量文件管理和 Git 操作。浏览器端只服务于本机回环地址。

## 2. 入口决策

采用 **`/story dashboard` 作为主入口**，而不是新增第 14 个 skill：

- Dashboard 是“查看当前工作区”的工具箱能力，放进 `story` 路由语义更自然；
- 服务端与静态资源跟随 `skills/story/` 分发，`story-setup` 的现有 `story*`
  复制规则无需扩张；
- 避免为一个本地 UI 同步新增 Claude/OpenCode/ZCode/Reasonix 多套独立命令面；
- 同时支持“打开工作台 / 看项目文件”等自然语言意图。

启动命令由 skill 从自身目录定位脚本，不假定仓库或全局安装路径：

```bash
node "<story-skill-dir>/scripts/dashboard-server.mjs" --root "<workspace>" --open
```

默认监听 `127.0.0.1`。启动输出可点击 URL；端口占用时自动尝试后续端口。

## 3. 信息架构

### 3.1 工作区识别

- **拆文库**
  - 标准结构：`拆文库/{书名}/...`
  - 兼容仓库旧 demo：根目录 `拆文库-{书名}/...`
- **写作项目**
  - 目录内出现 `正文/`、`大纲/`、`设定/`、`追踪/` 任一标志目录；
  - 最多向下发现三层，避免扫描无关的大型目录；
  - 拆文库内部不重复识别为写作项目。
- **可编辑文件**
  - `.md`、`.txt`、`.json`、`.yaml`、`.yml`、`.toml`；
  - 单文件最大 2 MiB；
  - 二进制文件只展示为不可编辑节点，首版不提供预览。

### 3.2 页面布局

```text
┌──────────────── 顶栏：OH STORY / 当前工作区 / 数量 / 本机状态 ─────────────┐
├───────────────────────┬────────────────────────────────────────────────────┤
│  资源树（320px）        │  文稿台                                             │
│  [拆文库] [写作项目]    │  breadcrumb · 文件名                  [编辑][预览]  │
│  搜索文件               │                                                    │
│  可折叠文件树           │                                                    │
│                        │  textarea 或安全 Markdown 预览                       │
│  本地工作区状态         │  行列 · 文稿统计 · 编码          已保存 · [保存]     │
└───────────────────────┴────────────────────────────────────────────────────┘
```

窄屏采用和成熟写作产品一致的单面板切换：默认展示文件树，打开文件后切到编辑器，
通过“返回文件”恢复资源树，避免把两块面板纵向堆叠成超长页面。键盘用户可通过
Tab、方向键、Enter 和 `Cmd/Ctrl + S` 完成主要操作。

## 4. 视觉设计

### 4.1 设计命题：专业写作工作台，不是展示型仪表盘

以用户提供的成熟写作产品截图和本机 `/Users/pite/makemoney/zenstory` 的工作台源码
作为信息架构参考，但不复制其业务代码。只保留本项目需要的文件管理与编辑能力，
明确去掉技能区、AI 助手和营销式数据卡：

- 全局顶栏固定为 48px，资源树固定约 320px，首屏空间全部服务于阅读和写作；
- 背景使用低噪声冷灰 `#f7f8fa`，编辑面为纯白，正文使用系统无衬线字体；
- 主强调色为克制的墨蓝 `#3777c3`，只用于活动页签、选中文件和保存动作；
- 成功、未保存、冲突分别使用语义绿、琥珀和红色，不依赖颜色单独传意；
- 面板以 1px 低对比分隔线连接，不使用套盒卡片、大面积阴影或纹理；
- 品牌统一为项目名 **OH STORY**，不另造产品名。

动效只服务于状态理解：树节点展开、编辑/预览切换和 toast 进入；尊重
`prefers-reduced-motion`。

### 4.2 组件细节

- 顶栏左侧使用紧凑的 `OH` 标记和 `OH STORY` 字标，不依赖外部图片或字体；
- 工作区统计收进顶栏，不再占用单独的概览横条；
- 文件树用内联 SVG 图标，目录、Markdown、文本、配置文件可区分；
- 活跃文件以墨蓝左线和浅灰蓝底表示，不做胶囊按钮堆叠；
- 编辑器占满剩余宽度，中文正文行高约 1.8；固定底栏持续显示行列、字数和保存状态；
- 空状态提供下一步说明，不放大号营销文案。

## 5. 技术设计

### 5.1 运行时

- Node.js 内置模块：`http`、`fs/promises`、`path`、`url`、`child_process`；
- 零生产依赖，静态资源为原生 HTML/CSS/JavaScript；
- Playwright 只作为根目录开发依赖；
- 服务端 API：
  - `GET /api/workspace`：分类文件树和统计；
  - `GET /api/file?path=...`：读取文本文件；
  - `PUT /api/file`：带 `expectedMtimeMs` 的乐观并发保存；
  - `DELETE /api/file`：带相同版本校验的单文件删除；
  - `GET /health`：测试和启动探活。

### 5.2 安全边界

- 默认且建议仅绑定 `127.0.0.1`；
- 所有读写路径先解码、规范化，再验证仍位于工作区根目录；
- 对最终真实路径做校验，拒绝借助符号链接逃逸；
- 仅允许白名单文本后缀，拒绝超限请求体和超限文件；
- 保存使用同目录临时文件 + rename，降低中途写坏的概率；
- 读取时返回 `mtimeMs`，保存时发现外部修改则返回 `409`，不静默覆盖；
- API 返回 `Cache-Control: no-store`，静态资源带同源安全响应头。

## 6. 测试计划

### 6.1 固定 demo

直接复用并整理仓库已有的 `demo/`：

- `demo/拆文库/盘龙/` 与 `demo/拆文库/曾将爱意私藏/` 验证拆文资产；
- `demo/长篇/让你管账号，你高燃混剪炸全网/` 验证真实长篇写作项目；
- demo 已整理到 `拆文库/{书名}`、`长篇/{书名}` 的正式目录规范；扫描器仍兼容
  存量工作区里的根目录 `拆文库-{书名}` 布局。

E2E 启动器先把现有 `demo/` 复制到系统临时目录，再测试保存，保证仓库样例不被改写，
也不为 Dashboard 另造一套与真实产物脱节的小说 fixture。

### 6.2 自动验证

1. **Node 单元/集成测试**
   - 正确发现拆文库和写作项目；
   - 排除 `.git`、`node_modules` 等目录；
   - 拒绝 `../` 与符号链接逃逸；
   - 读取、原子保存、确认删除和 mtime 冲突；
   - 非白名单后缀、过大正文和错误 JSON。
2. **Playwright E2E**
   - Dashboard 加载、概览和两个资料分类可见；
   - 搜索文件树；
   - 打开 demo Markdown，编辑、保存并确认删除；
   - `Cmd/Ctrl + S`、未保存提示、预览切换；
   - 桌面和移动视口无关键控件丢失；
   - 页面无未处理异常和 console error。
3. **仓库守卫**
   - `bash scripts/static-check.sh`
   - `python3 scripts/skill-numbering.py check`
   - 各 CLI adapter 静态检查
   - Node `--check` Dashboard 脚本

### 6.3 Claude Code / Codex 真实触发验收

除静态契约测试外，在隔离安装目录中对真实 CLI 做一次只读路由验收，避免把模型响应误当成
服务测试：

- **Claude Code 2.1.220**：用临时 inline plugin 装入当前 `skills/story/`，实际输入
  `/story dashboard`。CLI 的初始化事件注册了 `story:story`，响应准确返回
  `Dashboard 工作台` 段的 `127.0.0.1` 安全边界和完整 node 命令模板。
- **Codex CLI 0.145.0**：用临时 `CODEX_HOME` 安装当前 `skills/story/`，从仓库外的空白
  工作区实际输入 `$story dashboard`。CLI 随后读取
  `<isolated CODEX_HOME>/skills/story/SKILL.md`，确认命中 Dashboard 分支并返回同一命令模板。

路由验收不启动常驻服务；服务启动、`/health`、真实 demo 加载和编辑保存由 Node 集成测试与
Playwright E2E 独立验证。这样可以分别证明“平台确实触发 skill”和“被触发的服务确实可用”。

## 7. 交付阶段

1. 锁定入口、目录识别和 API 契约；
2. 实现只绑定本机的零依赖服务端；
3. 按专业写作工作台结构实现前端；
4. 添加 demo fixture、Node 测试和 Playwright 测试；
5. 接入 `story` 路由、README、Changelog；
6. 完成静态检查、跨适配器检查、浏览器截图和交互验收。

## 8. 验收标准

- `/story dashboard` 的 skill 指令能够从当前工作区启动服务并返回 URL；
- 页面明确分开展示拆文库与写作项目文件树；
- 白名单文本文件可读、可编辑、可保存或确认后删除，外部改动不会被静默覆盖或误删；
- 服务默认不对局域网暴露，路径逃逸测试通过；
- demo 驱动的 Playwright 测试覆盖加载、查找、编辑、保存、删除和响应式；
- 生产运行零 npm 依赖，完整仓库静态守卫无回归；
- 视觉呈现达到可直接给作者日常使用的完成度，而非线框或组件库默认皮肤。
