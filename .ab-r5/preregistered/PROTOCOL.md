# 预注册协议 — 「拒绝概述」扩章 × 跨模型确证（Round 5）

**冻结时间**：本文件、`analysis.py`、`chapter_pressure.json`、`chapter_classes.json` 与
`.ab-r5/harness/` 下全部脚本，在**任何一份确证成稿产生之前**一次性提交。提交后不修改；
如需修改，在文件末尾追加「协议偏离」条目，不得静默改写。

## 0. 本轮要解决的是上一轮留下的哪个问题

上一轮（`.ab-chronotope/preregistered/`，24 份成稿、4 章、单一写手模型）的结论是
**H1 未被确证**：NSD 分层平均差 +1.21，p = 0.283，CI [−0.58, +3.00]。
同时给出了一条明确的规划信息：**章间效应 SD = 1.78 比平均效应还大，
每格 n→∞ 时 SE 也只降到 ≈0.91 —— 要加的是章节数，不是重复次数。**

本轮据此改两件事，其余尽量不动：

1. **章节数 4 → 17**（同一本书第 4–20 章全量）。这是上一轮功效分析直接指出的唯一有效方向。
2. **写手模型 1 → 2**（GPT-5.6 与 Kimi），把「只在 GPT 上测过」这条外部效度缺口补上。

并新增一个上一轮没有的、真正决定「该不该合」的指标：**成对盲评偏好**。
上一轮的 NSD 只能回答「文本有没有按规则的方向变」，回答不了「读者侧是不是更好」。

## 1. 假设

**共同主假设（co-primary，各按 Bonferroni α = 0.025 判定）**

- **H1（机制）**：加入「拒绝概述」块（v2）相比不加（base），提高成稿中
  **不可替换具体细节数 NSD**。
- **H2（价值）**：在同章同模型的**成对盲评**中，v2 被判定为更值得追读的比例高于 base。

**预先声明的调节变量（moderator，α = 0.05，只用于「若主假设不成立，下一步怎么改」）**

- **M1（主）**：效应随**章节压力级**变化。压力级取自本书 `大纲/卷纲_第1卷.md`
  「章节定位分布」表，是本实验之前就存在的项目产物，逐字誊录进
  `chapter_pressure.json`，本轮不做任何重新判断。
  **方向预测：低压章（关系回收/铺垫）效应更大 → 斜率为负。**
  依据是 PR 自己的主张——被投诉的「平推/概述」形态主要出现在低压铺垫章，
  PR 同时改掉了 `writing-craft.md` 疏密表里低压章那一行。
- **M2（次）**：效应随**章节里「集合」的可落地性**变化，有序分数
  `none(+1) > concrete(0) > abstract(−1)`。分类由一名**只看细纲、不看任何正文、
  不知道有实验**的执行体（DeepSeek）在写作开始前完成，结果冻结在
  `chapter_classes.json`；同时用 Kimi 跑一遍报告一致率，但判定只用 DeepSeek 的标签。

**副作用假设（不做检验，只按阈值判定是否触发）**：v2 不降低情节点覆盖、
不增加题材串味、不把字数推出用户带。

## 2. 主指标

### NSD — 不可替换具体细节数

沿用上一轮的两段式量具（该量具的 ICC(2,1) = 0.869 已在上一轮确立），两段执行体互不见面，
**谁都不评价好坏**：

1. **抽取**：抽取员只拿到一份成稿 + 本章情节点清单，列出正文里**读者能复述出来的具体画面**
   （每条 ≤20 字，照抄原文）。只抽取，不判断，不知道臂别，也不知道存在对照。
   同一份成稿由 **3 名抽取员**各抽一次：两次互相独立的 GPT 抽样 + 一次 Kimi 抽样
   （实测两次同 prompt 的 GPT 抽取重合度 Jaccard = 0.63，确实是独立抽样而非同一份结果）。
2. **可替换性判定**：判定员（固定 GPT）**看不到正文**，只拿到三名抽取员候选合并去重后的清单
   + 本书设定一句话，对每条独立回答「原样挪到另一本书另一个角色身上还成不成立」。
   成立 = 通用填充，不计入；不成立 = 计入 NSD。分块判定（每块 ≤35 条）以防输出截断。

`NSD = 三名抽取员各自清单中被判为「搬不走」的条数的中位数`。

> 与上一轮的差异（须记录）：上一轮抽取指令带「全文最多 40 条」的上限，本轮实测该上限对
> GPT 抽取员是**紧的**（无上限时同一份成稿抽出 63 条），会把差异截掉，故本轮取消上限。
> 因此本轮 NSD 的**绝对量级与上一轮不可比**，只有臂间对照可比。

### PREF — 成对盲评偏好

同章、同写手模型、同 rep 的 base 与 v2 两份成稿并排给评审，问「哪一版更值得追读」。

- 评审只能是**没有写过这一对稿子**的两家（gpt 写的对子由 ds + kimi 评，kimi 写的对子由 ds + gpt 评），
  彻底排除自我偏好。
- **顺序反平衡**：每家各评两次，一次 base 在前，一次 v2 在前。每对共 **4 票**。
- 每对得分 `s = (v2 票 − base 票) / 4 ∈ [−1, 1]`；允许「平」。

## 3. 次要指标

- **COV**：情节点被实际落地的条数（抽取员在同一次调用中顺带判定，取三人中位数）。
- **OFF**：判定员标记为明显不属于本书题材/设定的条数。
- **TELL**：**情绪直陈句数**——直接告知情绪、或替读者把结论下掉的句子条数。
  由固定的 GPT 计数员产出。这是 PR 里第二条子规则（「情绪不许直接告知」）的直接机制指标。
  配对内写手恒定，计数员的系统性宽严在臂间对照中抵消。
- **CHARS**：`visible_chars_v1` 是否落在目标 ±15% 用户带内。

## 4. 样本与分层

| 分层 | 取值 |
|---|---|
| 章节 | demo 长篇《让你管账号，你高燃混剪炸全网》第 **4–20** 章，共 17 章 |
| 臂 | base ／ v2 |
| 写手模型 | GPT-5.6（`codex exec`）／ Kimi（`kimi -p`），各 2 次重复 |

`17 章 × 2 臂 × 2 模型 × 2 次 = 136 份成稿`，`17 × 2 × 2 = 68` 个成对比较，`272` 张偏好票。

**为什么不含第三家写手**：本机第三个可用 CLI 是 codewhale（DeepSeek-v4-pro），两条硬限制：

1. **上下文装不下真实 prompt**。真实部署的 narrative-writer prompt 为 78,542 个中文字符，
   超出其 64k 上下文，稳定返回空串（71,211 字符可跑，78,542 字符重试三次均为空）。
   为迁就它删掉内联参考文件，会同时改掉 base 臂的强度，是比「少一家写手」更严重的效度损失。
2. **长输出不可靠**。同一 CLI 在「列 10 条」时正常，「列 40 条」时返回空串，
   因此也不能当抽取员或情绪直陈计数员。

故 DeepSeek 在本轮只承担两件输出极短的工作：**章节结构分类员（M2）与成对偏好评委**。

**为什么不含第 1–3 章**：黄金三章在真实路径上还必读 `opening-design.md`，
prompt 构成与其余章不同，混进来会引入与臂无关的异质。

**为什么不换第二本书**：本机没有第二个带真实细纲/设定/追踪目录的长篇工程；
上一轮用拆文摘要手工拼的《盘龙》fixture 已被记为效度缺口，再拼 17 章只会放大它。
跨书泛化仍是本轮**未解决**的局限，见第 8 节。

## 5. 写作路径

两段式真路径，与 `workflow-chapter.md` 步骤 6–7 一致：

1. 按叙事顺序把情节点分成连续两组（前组 `ceil(n/2)` 条），同一 prompt 写前组临时 segment；
2. 真跑 `storyctl.py wordcount checkpoint`，把 `actual` 与 `remaining_user_range` 交回写手；
3. 写手只完成剩余情节点，不得为字数加剧情；
4. 两段一次组装成最终正文。

spawn prompt 由 `.ab-r5/harness/build_prompt.py` 生成：
narrative-writer 模板全文 + 命中必读条件的 5 份 agent-reference 全文 + 本书主题材卡 +
本书文风/题材定位/卷纲/追踪上下文/出场角色档案/上一章结尾/本章细纲全文 + 步骤 7 传参项。
**两臂唯一差异是「拒绝概述（密度层）」这一段文字**，其余逐字节相同（已用 diff 核对）。

各 CLI 的排版习惯（行首缩进、连续空行）在测量前统一归一化，两臂同样处理。

## 6. 统计分析（先冻结，见 analysis.py）

- **分析单元 = (章节 × 写手模型) 格**。每格取 v2 两次的均值减 base 两次的均值，得 `d`。
  估计量 = 全部 34 个格的 `d` 的平均。
- **NSD 主检验**：在每个 (章节 × 模型) 格**内部**置换臂标签，10000 次，双尾 p。
- **PREF 主检验**：配对内互换臂标签等价于分数取反，故用**符号翻转置换**，10000 次，双尾 p。
- **区间**：两个主指标都用**按章节整簇重抽**的 bootstrap（章节是主导的异质来源），10000 次，95%。
- **判定阈值**：`p < 0.025` **且** `bootstrap CI 下界 > 0`。
- **调节变量**：章节级效应对压力级（M1）/ 分类分数（M2）做最小二乘斜率，
  置换章节的标签 10000 次得 p，α = 0.05。
- **预先声明的敏感性分析**：LLM 评委已知偏好更长的文本。因此对 PREF 另跑一次
  只保留 `|Δ字数| ≤ 10% × 章目标` 的配对的分析，两个口径都报告。
- 次要指标只做描述性报告与区间估计，不做假设检验。
- **不做任何数据依赖的子集分析。** 某格运行失败时按实际 n 分析并在报告中标注。

## 7. 事先声明的判定表

| NSD | PREF | 结论 |
|---|---|---|
| 通过 | 通过 | 收益被确证，建议合入 |
| 未通过 | 通过 | 读者侧有收益，但不是靠 NSD 这条机制；可合入，同时改掉 PR 里对机制的描述 |
| 通过 | 未通过 | 文本按规则的方向变了，读者侧看不出好处 → **不建议直接合入** |
| 未通过 | 未通过 | 收益未被确证 → 按 M1/M2 决定是缩窄触发条件还是放弃 |

**副作用条件**（任一触发即须在结论中显式记录，即使主指标通过）：

- COV 在 v2 侧平均下降 ≥ 1 个情节点；
- OFF 在 v2 侧平均上升 ≥ 0.5 条；
- v2 侧字数带内率比 base 侧低 ≥ 25 个百分点。

## 8. 已知且不打算修的局限

- **单本书**。全部 17 章来自同一本都市/系统/文娱题材长篇，跨题材泛化未测。
- spawn prompt 是按 `workflow-chapter.md` 步骤 7 用脚本重建的，不是真实 skill 运行时产物；
  臂间逐字节相同，因此不威胁组间比较，但限制外部效度。
- 全部评审仍是 LLM，没有人类读者。NSD 衡量「细节的不可替换性」，
  PREF 衡量「LLM 评委作为读者的偏好」，都不等于「读者更愿意付费」。
- 写手拿不到 Bash，无法自查字数；两臂对称，但绝对字数偏短是系统性的。
- 作者（本次执行者）设计了 prompt、选了章节、写了分析脚本，未做执行者盲。
  缓解手段是本协议、分析脚本、两份调节变量标签与全部 harness 在数据产生前冻结提交。
- **先导试跑**：第 2 章跑过 4 份成稿用于调通管道与标定量具（抽取上限、判定分块），
  这些成稿与其测量**全部作废**，第 2 章也不在确证样本内。标定过程记录在本节，
  标定后再未改动任何测量指令。

## 量具验证（先导阶段完成，未改协议）

**位置偏好对照**：把**同一份正文**同时当作甲和乙交给评委，看它会不会硬挑出一个赢家。
三家评委各跑 5 次，共 15 次，**结果 15/15 全部判「平」**。
即本轮的成对偏好指令不存在「总是选第一个」的退化偏好，评委确实在读文本。
（先导阶段还观察到：在一对真实的 base/v2 上，两家评委在两种顺序下都选了排在前面的那一版——
这在同文对照为全平的前提下，最自然的解读是这一对本身难分伯仲，而不是评委位置锁死。
本轮因此在主口径之外，另报一个**只计「换序后仍选同一臂」的票**的稳健读数。）

## 协议偏离

### 偏离 1 — NSD 主口径从「逐抽取员中位数」改为「合并候选并集」（2026-08-26，确证测量开始前登记）

**改了什么**：`NSD = 三名抽取员各自清单中被判为「搬不走」的条数的中位数`
→ `NSD = 三名抽取员候选合并去重后、被判为「搬不走」的条数`。

**为什么**：本轮取消了上一轮的「最多 40 条」抽取上限（因为实测该上限是紧的，会把差异截掉）。
上限一去，三名抽取员的**穷尽程度**差异被放大：先导的一份成稿上，三人分别抽出 67 / 50 / 38 条，
对应的逐人 NSD 是 **19 / 5 / 4**。这个离散度主要来自「谁抽得更全」，不是来自成稿本身，
中位数因此变成了在测量抽取员而不是在测量正文。并集口径把三人的覆盖合起来用，
每份成稿只出一个数，抽取努力的随机波动在两臂间对称，不产生偏向。

**登记时点**：先导（第 2 章，成稿已作废）之后、**任何一份确证成稿被测量之前**。
先导本来就是协议第 8 节写明用于标定量具的环节。

**如何防止这次改动被用来挑结果**：原冻结口径（逐抽取员中位数）**照常计算并一并报告**，
作为敏感性分析。两个口径的结论若不一致，以**并集口径**为主并在报告里明确写出分歧。

### 偏离 2 — Kimi 侧重复次数从 2 次降为 1 次（2026-08-26，写作阶段中登记）

**改了什么**：样本表里 Kimi 写手的每格 2 次重复降为 1 次。GPT 侧不变（每格仍 2 次，68 份已全部完成，零失败）。
确证样本量因此从 136 份变为 102 份（GPT 68 + Kimi 34），成对比较从 68 对变为 51 对。

**为什么**：纯吞吐问题，与被测内容无关。真实部署的 spawn prompt 是 78,542 个中文字符，
Kimi CLI 处理这个长度的单次调用在并发下要 5–10 分钟，实测 10 并发时约 0.2 份成稿/分钟，
跑满 68 份需要 5 小时以上，且并发越高越容易超时重试。GPT 侧同样的 68 份在 25 分钟内跑完。
先把 Kimi 的 r1 跑齐（17 章 × 2 臂全覆盖），保证「两家写手 × 全部 17 章」这个结构完整；
r2 若之后有时间再补，补到多少就按实际 n 分析。

**对分析的影响**：分析单元仍是 (章节 × 模型) 格，共 34 格。Kimi 侧的格内从「两次均值之差」
变为「单次之差」，格内噪声变大；按章节整簇的 bootstrap 与格内置换检验都不要求各格 n 相等，
不需要改分析脚本。哪些格拿到了 r2 由写作作业的固定种子洗牌顺序决定，与臂无关，不产生选择偏倚。

### 偏离 3 — 抽取阶段加了一个纯调度用的 `--extractors` 参数（2026-08-26）

为了在 Kimi 还在写稿时先把 GPT 侧的抽取跑完，`orchestrate.py extract` 增加了
`--extractors` 参数，默认值仍是冻结的三名抽取员全集。它只决定**先跑谁、后跑谁**，
不改动抽取指令、判定指令、指标定义或任何一份 prompt。三名抽取员最终都会跑满。

### 偏离 4 — Kimi 账号级配额耗尽，退出写手与抽取员角色（2026-08-26 09:18，写作阶段中登记）

**发生了什么**：Kimi CLI 在写完 2 份成稿后开始对**任何**调用返回
`403 You've reached your 5-hour usage limit`（连一句话的探测调用也一样）。
这是账号级的 5 小时配额窗口，不是并发或超时问题——先前观察到的「慢」大概率也是同一原因的前兆。
GPT 侧 68 份在此之前已全部写完，零失败，不受影响。

**因此改动三处**：

1. **写手**：Kimi 退出。确证样本 = GPT-5.6 单一写手，17 章 × 2 臂 × 2 次 = **68 份**，
   51 对成对比较相应变为 **34 对**。已完成的 2 份 Kimi 成稿不纳入主分析（不成格）。
   → **跨模型泛化本轮未能完成**，降级为局限，见第 8 节。
2. **抽取员**：原定「两次 GPT 抽样 + 一次 Kimi 抽样」改为**三次互相独立的 GPT 抽样**
   （gpt / gpt2 / gpt3）。三次同 prompt 的重合度实测 Jaccard ≈ 0.63，确实是独立抽样。
   全部成稿一律用同一套三名抽取员，不出现「有的成稿有 Kimi 抽取、有的没有」的不一致。
   可替换性判定员本来就固定是 GPT 且全程看不到正文，这一条不变。
3. **偏好评委**：GPT 写的稿子只能由**没写过它**的家族来评，可用的只剩 DeepSeek。
   每对票数从 4 票（2 家 × 2 顺序）降为 **2 票（DeepSeek × 2 顺序）**。
   「评委与写手不同源」这条关键性质保住了，代价是每对的票数减半。

**没有改的**：任何一份 prompt、NSD 的定义、判定阈值、两个调节变量的标签、决策表。

**如果配额在本轮结束前恢复**：只在能**覆盖全部配对**的前提下补 Kimi 的偏好票，
不做只补一部分的操作；补与不补的两个口径都报告。
